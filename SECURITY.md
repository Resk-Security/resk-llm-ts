# Security Policy

## Supported versions

Security fixes are shipped on the latest published release. Please upgrade
before reporting an issue.

## Reporting a vulnerability

Do **not** open a public GitHub issue for a security problem.

Email **security@resk.fr** with:

- the affected package and version,
- a minimal reproduction or proof of concept,
- the potential impact,
- any suggested fix.

We aim to acknowledge reports within 3 business days and to publish a fixed
release as soon as practical. Credit is given in the release notes unless you
prefer to stay anonymous.

## Scope

This policy covers the source code of this repository and its published
package. Vulnerabilities in third-party dependencies should be reported
upstream; we still appreciate a heads-up so we can bump our floors.
